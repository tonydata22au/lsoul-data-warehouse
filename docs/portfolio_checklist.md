# LSOUL Portfolio Publication Checklist

## Before making the repository public

- [ ] Confirm you own the code or have permission to publish it.
- [ ] Remove service-account JSON keys.
- [ ] Remove API keys, tokens, passwords, connection strings, and `.env` files.
- [ ] Replace GCP project IDs and dataset names with placeholders where required.
- [ ] Remove proprietary raw data and exports.
- [ ] Remove confidential customer / employee information.
- [ ] Check notebook outputs for secrets or sensitive data.
- [ ] Check file history if anything sensitive was committed previously.
- [ ] Confirm source-system names can be disclosed.
- [ ] Confirm metrics and screenshots can be disclosed.
- [ ] Add a clear project description in README.
- [ ] Verify the setup instructions are reproducible without internal access.
- [ ] Open the README and notebook on GitHub and check their rendering.

## Recruiter-readability checklist

- [ ] README opens with a 2–3 sentence summary.
- [ ] Architecture is visible near the top.
- [ ] Tech stack is easy to scan.
- [ ] Folder names are descriptive.
- [ ] Results include measurable outcomes where permitted.
- [ ] One notebook demonstrates the analytical thinking.
- [ ] Contact / LinkedIn details are easy to find.
